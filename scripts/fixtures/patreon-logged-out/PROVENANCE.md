## Sanitization rules

1. Allowlist-first: every string that is not explicitly kept is replaced by same-length synthetic text.
2. Kept unchanged: JSON keys and structure, booleans, null, non-id numbers, and enum values (JSON:API `type`, post_type, access_rule_type, content_unlock_type, patron_status, mimetype, state, ProseMirror node/mark type, alignment, node_type, code_name, errors status/code, currency and similar closed sets).
3. Ids (resource, relationship, *_id, *_ids, ids inside URLs) go through ONE salted map; numeric ids stay numeric with the same length. Route keys use the same map.
4. Free text (title, name, summary, description, teaser, ProseMirror text, alt, caption, file name, ...) becomes random letters of the same length; spaces, newlines and ASCII punctuation stay. HTML keeps its tags; text and attribute values are replaced.
5. content_json_string and *_json_string are parsed, sanitized with the same rules, and serialized again (compact, sorted keys).
6. URLs keep scheme and Patreon hosts (other hosts become x-<hash>.example.invalid) and the path shape; slugs, vanity, hex and base64 segments are replaced; token-hash is `SYNTHETIC`; token-time is shifted.
7. Pagination cursors become `synthcursor-<hash>` through one map, so `meta.pagination.cursors.next` equals the next page's `page[cursor]`.
8. Every ISO date and unix token-time is shifted into the past by one fixed offset derived from the salt (order is kept; the offset is not published).
9. Private fields are dropped: email, session, csrf*, hashed_session_id, *phone*, cookie*, password, tokens. Only the content-type response header is kept.
10. Leak check on every run: original replaced strings (4+ chars), original ids (6+ chars), token-hash other than SYNTHETIC, e-mail patterns and cookie-like data. Any hit exits non-zero and writes nothing.
